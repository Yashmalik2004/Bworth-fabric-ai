# BWorth Phase 4: verified fabric dataset

Infrastructure for collecting **independently verified physical fabric samples** for cotton-composition
modelling. Initial target: **120 physical fabrics, 30 per band** (Low 30–40 %, Medium 50–66 %, High 80–95 %,
Very high 98–100 %, so 100 % cotton is included). No model is trained here.

```
datasets/phase4_verified/
├── images/<fabric_id>/<image_id>.jpg          photographs (4–6 per fabric)
├── metadata/
│   ├── fabric_registry.csv                    one row per physical fabric
│   ├── image_registry.csv                     one row per photograph (with SHA-256)
│   ├── verification_records.csv               evidence behind every composition label
│   ├── verification_documents/<fabric_id>/    lab reports, data sheets, invoices
│   └── manifests/                             generated: verified_training_manifest.csv, fabric_status.csv
└── documentation/
    ├── CAPTURE_PROTOCOL.md                    how to photograph
    ├── VERIFICATION_PROTOCOL.md               what evidence counts, how status is computed
    ├── DATA_DICTIONARY.md                     every column
    └── audit/dataset_audit_report.md          generated by the validator
```

## Workflow

1. **Register** the physical fabric. Tag the sample with its `BWF-xxxx` ID.
2. **Photograph** it per `CAPTURE_PROTOCOL.md` and upload the photos to that fabric.
3. **Attach evidence** per `VERIFICATION_PROTOCOL.md`. A reviewer accepts or rejects it.
4. **Validate**: `python -m data_collection.phase4.validate`. This refreshes the audit report, the fabric statuses
   and the verified training manifest. A non-zero exit code means integrity errors need fixing.

Data entry (all steps):

```
streamlit run data_collection/phase4/entry_app.py
```

Incomplete records can be saved; they stay `PENDING_VERIFICATION` and are never exported to the training manifest.

## Rules that make this dataset more trustworthy than CottonFabricImageBD

| CottonFabricImageBD problem (Phase 3 audit) | Rule here |
|---|---|
| Labels from unknown provenance | every label needs accepted evidence: lab test, or product-identified manufacturer/supplier document, reviewed |
| Same physical fabric under several labels/bands | one `fabric_id` per physical sample; registry duplicates and conflicting evidence are errors |
| Byte-identical photos copied between class folders | identical files rejected at entry; near-identical photos across fabrics flagged |
| Photos counted as samples; within-class grouping only | targets count fabrics; the manifest carries `fabric_id` for fabric-grouped splits |
| No way to re-check | SHA-256 per file, physical sample location, evidence documents kept |

Code: `data_collection/phase4/` (`registry.py` rules and storage, `validate.py` checks and report,
`entry_app.py` interface). Tests: `tests/test_phase4_dataset.py`.

**Git note:** the README, `documentation/` and the `metadata/*.csv` registries are tracked in git. Store them in backed-up storage, and check privacy/licensing before sharing.
